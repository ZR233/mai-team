## 所有权与数据流

| 层次 | 责任 |
| --- | --- |
| `mai-protocol` | 严格请求 DTO、源状态、配置修订、实际绑定快照、应用阶段及产品事件 |
| `mai-store` | schema 38 四张引用表、配置 CAS 与操作意图事务、物理绑定和 Agent 容器投影事务 |
| `mai-references` | 部署策略、异步验证、固定源身份、规范化指纹、租约和可恢复应用状态机 |
| `mai-docker` | 类型化递归只读挂载、最终计划与实际 inspect 比较、可写层快照、实际卷复用和定向资源清理 |
| `mai-runtime` | 把领域回调接到 canonical Thread、MCP、原有生命周期与产品事件；不另建执行器 |
| Web UI | 按项目拥有草稿，分别展示配置事实与应用事实，共用绑定编辑器 |

管理员的允许根属于部署文件，HTTP 请求不能扩大它。源验证拒绝外逃/破损/循环链接、硬链接、特殊文件、内部挂载、Git 元数据及不可信写权限；发布器按 Git blob 导出固定提交，保留原始字节，包括 LFS 指针，不执行工作树内容或下载 LFS 对象。

项目绑定先规范化再 CAS；配置与每个已有物理环境的操作意图同事务落盘。源身份、版本、别名和启用状态决定物理指纹，说明与排列变化仅更新模型事实。普通 Project/Agent 保存只能更新已有记录，不能删除重插、复活删除中的身份或覆盖新发布的容器 ID。

## Turn 与换代边界

全部 PL Git 依赖锁定到 `https://github.com/ZR233/anywork.git` 的主线提交 `8fd235ac748901ff0709c2fa65bb2475e8edf48b`。PL 的 Turn 准入 gate 与输入队列暂停独立；当前 Turn 保持已取得的 generation，后续 Turn 在目标环境就绪前等待，等待期间仍处理关闭、取消和持久化邮箱命令。

引用换代保留原 canonical Thread、输入身份和订阅。在 gate 关闭且没有执行中的 Turn 时，原位替换工具注册；`StopAndApply` 仅取消精确匹配的执行中 Turn，不取消等待准入的下一次输入，也不改变队列暂停策略。Thread 首次装配与环境换代共用 Agent 生命周期锁；激活回调不能递归装配父、祖父 Thread。

命令、文件、Git、上传、copy、stdin 与后台任务绑定固定租约。撤销旧 generation 先阻止新任务，再取消并排空已有资源；旧句柄不能按 Agent ID 自动切到新容器。词法路径和容器内解析后的实际路径分别检查，整个 `/references` 命名空间优先拒写。原有工作区的读写边界保持，引用仅加入读取根。

换代阶段为：等待空闲、排空、快照、创建、验证、重绑、发布、清理、完成。每阶段保存操作收据，容器/镜像用确定的 Agent 与 operation UUID 定位。提交镜像保存可写层；workspace、review view 和合法匿名卷按实际卷身份复用。镜像提交不代表卷数据备份。

DB 绑定发布先于 activation。此窗口被新修订取代时，已发布候选必须停止保留，成为下一次换代的旧环境；只有未发布候选才能直接删除。失败保持 gate 关闭，旧容器停止，不恢复旧授权、不退回基础镜像。缺少旧环境和有效恢复收据时返回 `environment_recovery_unavailable`，要求恢复成套备份。

启动先恢复引用操作，再执行孤儿清理与自动审查。快照回收保护当前绑定、未完成及失败操作、存活 clone、Docker 中所有仍引用镜像的容器和其他产品库的 owner。创建到发布之间持有资源读锁，回收使用写锁；不用 force/prune，合法备份或归属不明确的镜像保留。

模型清单只取实际 applied snapshot；宿主路径不作为清单字段。参考源码中的 `AGENTS.md` 和 skills 只作为可显式读取的资料，不能自动注册为项目指令或技能。

## 默认值与命令输出

每项目最多 16 条绑定，验证并发 1、应用并发 2，排空上限 60 秒。模型命令输出上限 32 KiB；单命令两个流的捕获落盘总量硬上限 64 MiB，超限终止命令和其后代并报告专门终态。无匹配退出码、执行超时、模型输出截断和捕获超限分别记录。

配置保存、等待空闲、应用中、失败、全部已应用分别展示。SSE/refetch 更新服务器事实，不能覆盖本地草稿；CAS 冲突保留输入，并提供加载最新配置的明确操作。停止并应用使用确认弹窗。

## 迁移和生产切换

离线工具属于 `mai-store`，二进制名为 `mai-migrate-references`：

```bash
mai-migrate-references check --database /path/to/mai-team.sqlite3
mai-migrate-references migrate --database /path/to/mai-team.sqlite3 --backup /path/to/schema37-backup.sqlite3
```

schema 37→38 迁移在停服库执行，保留产品记录、会话目录和历史。`check` 报告 schema、完整性、JSON 有效性与记录数量；迁移前后的报告都归档。

部署顺序：隔离验收完成后，记录并暂停自动审查，排空工作；备份二进制、unit、配置、完整数据目录、实际容器可写层镜像和所有实际卷。停服迁移后原子替换二进制，使用原数据目录，通过独立部署文件启用参考源策略。等待健康、历史、SSE、MCP 和 Web UI 就绪，再登记固定 Linux 源并为 `tgoskits` 保存 `alias=linux`，等待所有已有物理环境应用完成后恢复原自动审查设置。

生产回退使用同一时间点的二进制、配置、产品库、会话、镜像和卷备份。覆盖切换后的业务写入前，必须明确恢复的数据时间点及其后新增写入的处理方式。注销源和删除项目只清理自身元数据/资源，不删除管理员发布的源码原件。

- `scripts/references/test-publisher.py`：固定提交、脏工作树、archive 属性、gitlink、LFS 和摘要互操作。

- `shared_references_runtime`：真实 canonical 工具、Turn 准入、child/grandchild、文件传输、stdin、输出边界、项目创建、自动 Reviewer、声明匿名卷及提示注入资料化。
- `scripts/references/benchmark-linux.py`：真实 Linux 源冷/热搜索、并发 1/4/8、延迟与资源数据；冷读仅对这些源码文件使用 `POSIX_FADV_DONTNEED`，不清空全机缓存。
- `playwright.live.config.ts`：真实隔离服务的桌面、平板和手机视口；常规 Playwright 使用 API 夹具，单独报告。

隔离根固定为 `/mnt/docker_nvme/mai-references-acceptance/20261015-shared-sources`，Docker socket 为 `/run/mai-reference-acceptance-docker/docker.sock`。故障脚本拒绝生产 socket。`docker_offline`/`enospc` 是精确命令与 Agent 范围的 CLI 返回错误注入，未停止生产 Docker 或填满主机磁盘；关闭超时使用真实 60 秒等待。每轮原始 JSON、日志、截图、迁移报告和最终产物校验值分别保留，不能把边界、跳过或未运行项目写成通过。
