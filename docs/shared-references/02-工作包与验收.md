## B. 实施步骤的具体检查

### W0：不要跳过的基线盘点

记录 `git rev-parse HEAD`、Cargo.lock 里的 PL git revision、Docker Server/CLI 版本、kernel、存储驱动、local context、默认/自定义镜像 ID。`docker --version` 只代表客户端，不能代替 Server 版本。

识别全部入口：创建项目 Maintainer、手动普通 Agent、spawn/clone child、grandchild、自动 reviewer、恢复 agent、工作区恢复、文件上传下载、copy_to、write_stdin、后台命令、MCP reconcile、项目/Agent 删除、启动 orphan cleanup。

确认受控参考根不与应用数据目录、会话目录、凭据、原项目可写目录和其他管理员工具缓存重叠。

### W1：校验不能只做在 UI

先写不变量测试，再实现：路径组件前缀、别名语法、重复 ID/源/alias、关闭缺失源、严格 JSON、源身份不可变、manifest 摘要与 symlink/type 验证。扫描使用阻塞任务/专用 worker，禁止把 Linux 所有文件全文聚合成一个内存对象。

没有 manifest 的目录必须用“目录快照 + 摘要”语义，不能标记 git verified。每次 publish 更新配置版本，但同样内容重复保存不增版。

### W2：先修存储写入，再加外键

父对象正常保存必须不产生删除。测试同一 Agent 连续保存模型/运行状态后 binding 和 apply_operation 仍存在。环境绑定事务是唯一物理 ID 发布入口；普通 full summary 保存不得覆盖它。

迁移必须在旧 schema 的真实 fixture 上测试，而不只在全新空库测试。模拟中途异常必须整个事务回滚，旧 schema 标记不变。测试 DB locked 和错误 JSON 时不把配置当作空数组。

### W3/W4：不要漏“非任务进程”

既有 Agent 的 idle 只代表没有模型 turn，不表示容器里没有用户后台 daemon、MCP 或命令会话。切换必须通过生命周期关闭这些进程/容器；先确认旧执行停止，再启动候选。

当前旧选择器会选任意 agent 标签容器，新逻辑要用 operation/generation 与已发布 binding 选择。清理 old 不得调用会删候选的广义 delete_agent_containers。

镜像层数据、workspace volume、其他合法匿名 volume 分开验证；不能只测 `/workspace/repo` 一个文件就声明“环境保留”。

### W5：三条独立通道都要测

`read_file/list_files/apply_patch` 是一条，任意 shell exec 是另一条，上传/copy 是第三条。只在一个工具上加过滤不等于原件安全。最终需要宿主文件摘要前后不变和容器挂载确为 RO 的证据。

### W6/W7：成功语义统一

HTTP 保存成功和 Docker 应用成功是两件事；UI、事件、文档必须同样区分。实时事件不修改本地草稿。服务失败后重试 GET 能得到正确事实；换页回来不丢用户输入、不将别的项目结果套进当前页。

## C. 验收矩阵

测试场景中的故障和攻击只使用测试库、临时源码目录和测试容器。不得在真实 Linux 目录上验证写入是否失败。

| ID | 类型 | 场景与步骤 | 通过条件 |
|---|---|---|---|
| T01 | 单元 | alias 非法、过长、重复 ID/源/别名、bindings=null/缺失 | 422；无持久化/容器副作用 |
| T02 | 单元 | allowed `/srv/ref`，输入 `/srv/ref-evil`、`..`、相对路径、逗号/换行 | 全拒绝；按组件而非字符串前缀 |
| T03 | 文件 | 顶层/祖先 symlink，内部外链/断链/循环 | 精确错误路径；不跟随导出宿主文件 |
| T04 | 文件 | 内部 symlink 指向同一源内文件 | 可登记、可只读访问；不因 blanket 禁 symlink 破坏合法源码 |
| T05 | 文件 | socket/FIFO/device/hardlink/子挂载/.git | 不可 ready；没有静默跳过 |
| T06 | 文件 | 源路径不存在、不是目录、发布者不可信、可被他人替换 | 拒绝；不自动 mkdir/chmod/chown 原件 |
| T07 | 发布器 | 固定 commit、有未提交文件、有 export-ignore/export-subst | 导出 commit 对象原文，非工作区；不受 archive 属性过滤 |
| T08 | 发布器 | submodule/gitlink、LFS 指针 | 子模块显式失败；LFS 保留 pointer 并文档说明，不假装取到对象 |
| T09 | 注册 | 验证很慢或服务在 validating 时重启 | API 202、可看进度；重启恢复验证；未 ready 不可绑定启用 |
| T10 | 存储 | 两客户端相同 expected_revision 同时保存不同配置 | 恰一个成功；另一个 409，不能 last-write-win |
| T11 | 存储 | DB 写失败、事件发布失败、响应丢失 | DB 失败不改内存；事件失败可 GET/重启恢复；无伪成功 |
| T12 | 存储 | project/agent 正常反复保存、模型设置变化 | 引用配置、binding、operation 不消失，container ID 不被旧 summary 覆盖 |
| T13 | 迁移 | 37 旧库升级，含项目/Agent/历史；新库初始化 | 行数和会话文件保留，约束相同，标记正确；不清库 |
| T14 | 容器 | 两个 Agent 引用同 source | Mounts.Source 相同、RW=false；源大小不按 Agent 增长 |
| T15 | 容器 | 普通非空引用重复 ensure 和进程重启 | 同一匹配容器复用，不每次 commit/recreate |
| T16 | 容器 | 从有引用改为 [] | 旧真实挂载消失；不能因 mounts 为空复用旧容器 |
| T17 | 容器 | 仅修改说明/排列顺序 | container ID/generation 不变；下一 turn 清单更新 |
| T18 | 覆盖 | 创建项目时已有引用 | Maintainer 首次工具调用可读，不短暂以空集 Ready |
| T19 | 覆盖 | planner/explorer/executor/reviewer/child/grandchild | 均继承可信 project_id 引用；不遗漏 CloneFrom |
| T20 | 覆盖 | 自动 PR 审查 | 新引用可读；原 `/project/repo` 的版本/RO 不变；审查原写限制不变 |
| T21 | 覆盖 | B 项目与非项目 Agent 未绑定 A 的私有 fixture | 无 A 挂载；文件工具无法通过 A 的绑定读取；不声称阻止公共源码网络下载 |
| T22 | RO | root shell append/touch/remove/rename/chmod/hardlink | 都不能修改参考原件；宿主前后内容摘要一致 |
| T23 | RO | mount remount/umount 尝试、Docker socket 探测 | 无 CAP_SYS_ADMIN/privileged/socket；不得改 RO；测试环境隔离 |
| T24 | 工具 | read_file/list_files/stat/read_bytes 读引用 | 实际注册工具成功，非仅 cat 成功 |
| T25 | 工具 | apply_patch、上传、copy_to、workspace symlink 指向引用 | 写入口拒绝；不扩大其他工作区写权 |
| T26 | sidecar | MCP sidecar 对同引用读写；Agent 换代 | 可读不可写；旧 sidecar 退出、旧 handle 不能执行 |
| T27 | 保留 | `/usr/local` 标记/已安装包 + workspace 未提交文件 + 匿名卷文件 | 受控换代后三类数据保留；base/effective image 不混淆 |
| T28 | 并发 | 活动 turn 中修改配置，随后内部 continuation/inbox | 当前 turn 固定旧 lease；下一 turn 在新配置 ready 前不执行 |
| T29 | 并发 | apply、spawn、delete、recover 同时触发 | 一个执行 owner；新 child 目标来源可信；无死锁/悬挂全局锁 |
| T30 | 并发 | G1 应用途中再保存 G2/G3 | G1 不能覆盖新目标；状态真实，最后收敛到最新目标 |
| T31 | 故障 | 逐阶段在 commit/candidate/create/rebind/publish/cleanup kill server | 根据收据恢复；不误删候选；不复活旧授权；无重复 owner |
| T32 | 故障 | 磁盘满、Docker offline、必需 MCP 失败、close 超时 | failed/blocked + 可重试；旧容器 stopped 保留，不退回基础镜像 |
| T33 | 故障 | old 与 snapshot 缺失；外部源根被替换 | 明确不可恢复/身份错误；不装空目录或静默成功 |
| T34 | UI | dirty 草稿时收到 SSE/refetch/模型状态变化 | 草稿保持；服务器状态独立更新 |
| T35 | UI | 删除中间行/第一行；切项目/标签；验证结果乱序 | 行 ID/焦点/字段值不错位；不串项目；旧校验不生效 |
| T36 | UI | CAS 冲突、网络失败、重复提交、源验证失败 | 保留输入；字段错误；明确冲突；没有错误 toast “全部已应用” |
| T37 | 安全 | 未登录请求、Agent 直连后端、伪造管理 header | 401/403，路径不存在与否不可探测；后端没有代理旁路 |
| T38 | 安全 | 列表/说明含脚本 HTML 或 AGENTS.md 提示注入 | UI 安全显示；模型只作为资料；不自动注册其 skills |
| T39 | 清理 | 删除引用/项目/Agent；注销被引用源 | 原件不删；引用中注销 409；operation 资源先收敛再删父记录 |
| T40 | 性能/语义 | 真实 Linux：冷/热搜索、并发 1/4/8、大输出、无匹配/超时 | 报 p50/p95 与资源数据；截断/超时和无匹配区分；不 hash/扫描源以外无关库；不把 rg -m 当全局上限 |

## D. 必须运行的命令与证据

仓库原有命令（工作目录为 repo 根；安装依赖按固定 lockfile）：

```sh
cargo fmt --all -- --check
cargo test -p mai-docker -p mai-store -p mai-runtime -p mai-protocol
# 新 crate 加入后：
cargo test -p mai-references

cd crates/mai-server/web
npm ci
npm run typecheck
npm run lint
npm run test
npm run build
npm run test:e2e
```

真实 Docker 测试建议用 feature `docker-integration` 显式启用（需实现，不是现有命令）：

```sh
cargo test -p mai-docker --features docker-integration --test references -- --test-threads=1
```

CI 该任务缺少 daemon 或权限必须失败/明确跳过并禁止发布，不能普通 cargo test 绿色就认为 RO 已验收。固定测试镜像 digest；调用前准备镜像，不在测试中随机拉 latest。

提交证据放入功能 PR 附件或 `artifacts/reference-acceptance/`（不要提交原源码、token 和用户历史）：

```text
baseline.txt
unit-tests.txt
migration-report.txt
source-manifest-sample.json
mounts-before.json / mounts-after.json
host-fixture-digests-before.txt / after.txt
environment-preservation.txt
recovery-fault-matrix.md
ui-e2e-results/
search-performance.md
security-gate-report.md
```

## E. 负责人签收条件

技术负责人检查没有绕过领域规则的创建分支；容器负责人签收真实写保护与数据保留；前端负责人签收草稿、状态、确认语义；运维签收备份/迁移/回退及凭据隔离。

只有接口能保存路径、单个容器能 cat 文件、mock Docker 输出符合预期、截图展示了 References 标签，都不单独构成功能验收。
