# 接口补充与核心伪代码

本文件所有 Rust 方法名均为建议新增/重构接口，不声称可直接对当前版本编译。具体适配现有 PL API 时以 Cargo.lock 锁定依赖为准，不能凭下面伪代码发明 pl-core 函数。

## 1. 数据结构的归属与不可变性

```rust
/// 一个已发布源码树的可挂载身份；仅由源验证器创建。
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ResolvedReference {
    pub source_id: Uuid,
    pub canonical_source: PathBuf,
    pub source_device: u64,
    pub source_inode: u64,
    pub tree_digest: String,
    pub container_path: String,
    pub provenance: ReferenceProvenance,
}

/// 给特定 generation 的物理引用快照，不重新查询父 Agent 或 UI 草稿。
#[derive(Debug, Clone)]
pub struct AppliedReferenceSnapshot {
    pub project_id: ProjectId,
    pub configuration_revision: u64,
    pub fingerprint: String,
    pub sources: Vec<ResolvedReference>,
    pub descriptions: BTreeMap<Uuid, String>,
}

/// 模型只得到这个投影，不能得到 canonical_source/dev/ino 等主机细节。
#[derive(Debug, Clone, Serialize)]
pub struct ModelVisibleReference {
    pub source_id: Uuid,
    pub name: String,
    pub version: String,
    pub container_path: String,
    pub description: String,
}
```

必须用构造器约束 ResolvedReference，实际字段尽量私有；上面为说明形状展开。描述/排序变化可更新同 generation 的元数据快照，工具 lease 的物理源集合不变，下一 turn 接收新清单；不能因此替换实际 container_id。

## 2. 项目配置服务

```rust
/// 产品服务：管理登记源和项目绑定，不负责 Thread 执行。
pub struct ReferenceService {
    store: Arc<MaiStore>,
    policy: ReferenceSourcePolicy,
    wake_apply: Notify,
    // 只在短准入/保存事务使用；不把慢文件扫描放进项目锁。
    project_gates: ProjectGateRegistry,
}

impl ReferenceService {
    pub async fn replace_project_bindings(
        &self,
        project_id: ProjectId,
        input: ReplaceProjectReferencesRequest,
    ) -> Result<ProjectReferenceView> {
        let normalized = validate_binding_fields(input.bindings)?;
        // 已禁用/被移除的坏目录不要求恢复存在性。
        let validated_sources = self.resolve_enabled_sources(&normalized).await?;
        let gate = self.project_gates.lock(project_id).await;
        // 存储事务内再次核对 source 状态、project 存在性和 revision。
        let committed = self.store.compare_and_swap_references(
            project_id, input.expected_revision, normalized, validated_sources,
        ).await?;
        self.publish_committed_snapshot(&committed);
        drop(gate);
        self.wake_apply.notify_one();
        // 事件失败不会撤销 durable config；调用者可 GET 同一版本核实。
        self.publish_change_event_best_effort(&committed).await;
        self.view(project_id).await
    }
}
```

通知只用于唤醒一个调度 owner，数据库待办才是真相；worker 每轮排空持久待办，并设置低频补偿检查，避免崩溃或通知竞态丢失应用。等待方先登记通知再检查条件。

单元测试将路径验证、store、Docker side effects 注入，不修改测试进程环境变量来模拟 DOCKER_HOST。新 trait 给出中文职责与 Send 的 RPITIT 签名。

## 3. Docker 只生成机制，不决定授权

```rust
/// 封装验证过的最终 Docker 创建参数。
pub struct CreateManagedEnvironment {
    pub owner: AgentEnvironmentOwner,
    pub image_id: String,
    pub workspace: ContainerVolumeMount,
    pub additional_mounts: Vec<ContainerMount>,
    pub options: ValidatedContainerOptions,
}

impl DockerClient {
    pub async fn inspect_environment(
        &self,
        expected: &AgentEnvironmentPlan,
    ) -> Result<ExistingEnvironment> {
        let candidate = self.lookup_published_generation(expected.agent_id).await?;
        match candidate {
            None => Ok(ExistingEnvironment::Absent),
            Some(actual) => {
                let diff = compare_environment(expected, &actual)?;
                if diff.is_empty() {
                    Ok(ExistingEnvironment::Matching(actual.verify()?))
                } else {
                    Ok(ExistingEnvironment::ReconfigurationRequired(diff))
                }
            }
        }
    }
}
```

compare_environment 是纯函数；测试覆盖 source/target/RW/subpath/workspace/有效 image 以及移除全部引用。任何 branch 不能因参数为 [] 放弃核对旧挂载。

## 4. 安全应用协调器

```rust
/// 位于运行时协调模块，负责现有 Thread/命令/MCP 与 Docker 的生命周期排列。
async fn apply_agent_references(
    runtime: &AgentRuntime,
    agent_id: AgentId,
    requested_policy: ReferenceApplyPolicy,
) -> Result<ApplyStatus> {
    let lifecycle = runtime.lock_agent_lifecycle(agent_id).await;
    let desired = runtime.references.desired_for_agent(agent_id).await?;
    let active = runtime.verified_environment_binding(agent_id).await?;

    if active.physical_reference_fingerprint() == desired.fingerprint {
        runtime.commit_metadata_only_update(active, desired).await?;
        return Ok(ApplyStatus::Applied);
    }

    let operation = runtime.begin_or_resume_apply(agent_id, &desired, requested_policy).await?;
    runtime.close_new_turn_admission(agent_id, operation.id()).await?;

    // 这里不能把 lifecycle 锁持有到需要同锁的 turn 结束回调；实际实现必须
    // 将锁表达成可重入阶段所有权/操作令牌，或释放后用 operation generation 再核验。
    // 伪代码的变量用于表示“一个操作拥有换代权”，不要求一个 MutexGuard 横跨等待。
    drop(lifecycle);
    runtime.await_idle_or_cancel_for_operation(&operation).await?;

    let lifecycle = runtime.lock_agent_lifecycle(agent_id).await;
    runtime.validate_operation_ownership(&operation).await?;
    runtime.await_durable_and_close_resident_thread(agent_id).await?;
    runtime.shutdown_commands_and_mcp(agent_id).await?;
    runtime.stop_old_container(&operation).await?;

    let snapshot_image = runtime.snapshot_old_environment_or_use_initial_image(&operation).await?;
    let plan = runtime.final_environment_plan(&operation, &snapshot_image).await?;
    let candidate = runtime.create_candidate(&operation, &plan).await?;
    runtime.verify_candidate(&candidate, &plan).await?;
    let prepared = runtime.restore_thread_and_tools_blocked(agent_id, candidate.lease()).await?;

    // project revision、source 状态、基础环境参数都要 fence 检查。
    // Agent 生命周期所有者保持不变；项目短锁内不再等待其他 Agent 锁或慢资源。
    let publish_guards = runtime.lock_project_for_publish(agent_id).await?;
    runtime.check_desired_still_matches(&operation, &plan).await?;
    runtime.publish_binding_transaction(&operation, &candidate, &plan).await?;
    runtime.publish_prepared_owner_and_open_admission(prepared).await?;
    drop(publish_guards);

    // 只清理 operation 记录中的旧 ID，禁止按 agent 标签清空所有容器。
    runtime.cleanup_old_generation_or_record_pending(&operation).await?;
    Ok(ApplyStatus::Applied)
}
```

实现时每次外部副作用都要在 operation 中先记意图/后记结果；上面的 `?` 不代表可以丢失阶段收据。出错路径持久化 typed error，保持准入关闭，保留或定向清理候选；不能自动恢复旧授权。短发布区外存在目标变化时，prepared owner 仍 blocked，不会执行模型。

镜像配置或 workspace 参数在引用换代中变化时返回配置冲突/中止旧目标，不把旧快照偷偷当作“已经应用新基础镜像”。本轮引用修改和基础镜像更换分两项操作，不承诺后者同样保留旧安装状态。

## 5. 写入拒绝顺序

```rust
fn authorize_write(policy: &WorkspaceFilePolicy, lexical: &ContainerPath) -> Result<()> {
    if within(lexical, "/references") {
        return Err(ReferenceError::ReadOnlyReference);
    }
    policy.authorize_original_write_scope(lexical)
}

async fn resolve_for_write(lease: &AgentEnvironmentLease, path: &str) -> Result<ContainerPath> {
    lease.ensure_not_revoked()?;
    let lexical = normalize_container_path(path)?;
    authorize_write(lease.policy(), &lexical)?;
    let resolved = resolve_inside_same_container(lease.container_id(), &lexical).await?;
    authorize_write(lease.policy(), &resolved)?;
    Ok(resolved)
}
```

rename 源和目标分别检查；patch 一次多文件先预检全部路径再调用既有 patch 实现，不能在已写一半后才发现 reference 目标。不存在的新文件解析允许规范化父路径+文件名，不把 readlink -f 失败直接降级为未校验路径。

最终 Docker RO 仍是原件写保护；该应用策略改善错误信息并保护 copy/上传等路径，不宣称约束任意 shell 的所有行为。

## 7. 树摘要互操作细节

随包 Git 发布器的 `manifest_digest` 为：

```text
SHA256(UTF8(JSON({"format":"mai.reference.tree.v1","entries":entries},
    sort_keys=true, separators=(",",":"), ensure_ascii=false)))
```

entries 按 Unicode 路径字典序排列，每项固定字段 path、git_mode、git_blob、kind、size、sha256。普通文件 sha256 对字节计算；symlink 对链接目标 UTF-8 字节计算；size 为相应字节长度。不能 hash 带缩进的整个 source-manifest.json，也不能包含生成时间或源宿主路径。

服务端验证 manifest 是可信管理员发布的元数据后，逐项验证文件路径/类型/字节摘要，并核对没有额外文件。`git_blob` 可按 Git blob header+内容重新计算；provenance 的 commit 与 tree 归属依赖可信发布流程，摘要不是签名。手工目录采用独立 `directory_tree.v1` 摘要域，条目不需要 git_blob，不能与 Git 发布摘要混用。
